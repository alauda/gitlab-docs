## v18.8.2

### Product Name Change

To comply with the GitLab trademark guidelines, the product is renamed from **Alauda Build of Gitlab**
to **Alauda Toolchain Code Repository E1**. The new name appears in the Operator Hub listing
(display name, description and icon), the platform catalog entry (now **Code Repository Operator**),
the monitoring dashboards and the product documentation, and user-visible "GitLab" wording in
these places is replaced with neutral terms. A trademark notice is added to the operator
description and the documentation.

The rename changes what users see, not how the operator is installed or used:

- The operator package name stays `gitlab-ce-operator`, so the Subscription, the channel and the
  upgrade path from earlier versions are unchanged.
- The custom resource stays `GitlabOfficial` (`gitlabofficials.operator.alaudadevops.io`).
  Existing instances need no change and keep running after the upgrade.
- The bundled software is still the GitLab community edition, and its own web interface is not
  rebranded.

When searching the Operator Hub or Marketplace for this operator, look for
**Alauda Toolchain Code Repository E1** instead of the previous name.

### Features and Enhancements

#### Alauda Toolchain Code Repository E1

Instances can now publish their web entry through Gateway API (`HTTPRoute`) instead of Ingress, so
the operator can be used on clusters that provide only Gateway API. The High Availability and AML
templates expose the Gateway settings. See
[Gateway API Access](../install/03_gitlab_deploy.mdx#gateway-api-access) for new instances, and
[Migrate an Existing Instance from Ingress to Gateway API](../howto/09_migrate_ingress_to_gateway.mdx)
for instances that already use Ingress.

The bundled GitLab community edition stays at v18.8.11.

A troubleshooting article is added for PostgreSQL running out of shared memory during database
migration. See
[PostgreSQL Out of Shared Memory During Database Migration](../trouble_shooting/04_pg_max_locks_per_transaction_error.mdx).
Another one covers clone URLs and links that miss the port when users reach the instance through
Ingress or Gateway API on a port other than 80/443, for example a NodePort. See
[Clone URLs and Links Miss the Port When the Entry Is Not on 80/443](../trouble_shooting/05_external_port_missing_in_urls.mdx).

### Security

The Ruby runtime in the component images carries the backported Onigmo regular expression overflow
fixes for CVE-2026-110264. The operator manager and the console plugin images are rebuilt on an
updated non-root distroless base, which picks up the fixed `tzdata` and `ca-certificates`
packages. The console plugin image previously ran as root and now runs as a non-root user.

## v18.8.1

### Features and Enhancements

#### Alauda Toolchain Code Repository E1

The bundled GitLab community edition moves from v18.8.6 to v18.8.11, which carries the upstream
patch releases for the 18.8 line.

This version is validated on ACP v4.4 in addition to v4.0 through v4.3.

### Security

Component images are rebuilt on Go 1.26.7 with the gitaly, OpenTelemetry and `golang.org/x/sys`
dependencies advanced past their published advisories, and the `go-git` modules updated to their
fixed releases. The manager image no longer ships the parts of its kodata tree that were never
read at runtime, which removes the third-party content scanned along with them.
